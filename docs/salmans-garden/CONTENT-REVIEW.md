# مراجعة المحتوى وضمان الجودة — «حدائق النور»

> **القرار (2026-10-11، قرار §12 رقم 5):** المراجعة والتحقق وضمان الجودة أقوم بها أنا — بحث ومقابلة على المصادر، وفحص لغوي، وفحص عمر الطفل، وفحص تقني — بدل انتظار مراجع بشري. ويبقى **مصدر كل قصة مذكورًا مع رقمه ورابطه** حتى يستطيع ولي الأمر إعادة التحقق بنفسه في ثانية.
> **القاعدة التي لا تتغير:** لا يُسجَّل صوت، ولا يُعرض نص على الطفل بوصفه نهائيًا، قبل أن يمرّ على هذا الملف ويُسجَّل له صفّ في §3 بالحالة ✅.

المرجع: [`PLAN-ISLAMIC-PHONICS.md`](PLAN-ISLAMIC-PHONICS.md) §7 (الكتابة) و§11 (المراحل) و§8.4 (قواعد التصوير).

**قاعدة الفشل:** أي فحص يسقط ⇒ تُعاد الصياغة وتُسجَّل المحاولة في §3 بحالة ⬜ حتى تنجح الفحوص الستة.

## 2. الفحص التقني بعد كل دفعة

```bash
npx vitest run
npx eslint src tests && npx prettier --check "src/**/*.{js,jsx}" "tests/**/*.{js,mjs,jsx}"
npm run build
```

- **اختبار المحتوى:** كل قصة تدخل التطبيق يجب أن يكون لها مصدر قابل للتتبع؛ يُضاف اختبار `tests/salman-content-sources.test.mjs` في المرحلة P0 يتحقق أن كل قصة في بيانات الحديقة لها `source` ورقم/آية، ويفشل إن وُجدت قصة بلا مصدر.
- **ميزانية الأصول** (`PLAN-ISLAMIC-PHONICS.md` §8.3): ≤ 200 KB صور للطيار، ≤ 1 MB للبرنامج كله. تُقاس بـ `du -sh public/salman/art` قبل/بعد كل مرحلة.
- **عربة الأوفلاين:** أي أصل جديد يدخل precache، ويُشغَّل `tools/salman-offline-check.mjs` في مراحل P2 وP5 وP6.

## 4. ما يتغيّر في المصادر بعد المراجعة

- **لا يُعدَّل نصّ الكتابين المنقول** (`source/alphabet-with-the-*.md`): يبقى مرجعًا كما هو.
- الإضافات تبقى في `source/additions-fa-and-numbers.md` ومعها سجل التحقق، وأي تصحيح لاحق يُكتب فيه لا في نصوص الكتابين.
- **الفرق المتبقي عن المراجعة البشرية** يُوثَّق هنا بصراحة: مراجعتي آلية-بشرية بالمقابلة على المصادر وفحص اللغة والبنية، وليست فتوى ولا تخريجًا مستقلًا. لذلك يظهر مع كل قصة رابط مصدرها، ويستطيع ولي الأمر أو أي معلّم إيقاف أي قصة بتعديل صفّها هنا إلى ⛔.
